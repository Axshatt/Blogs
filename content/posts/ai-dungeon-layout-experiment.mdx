I'm building a small indie game on the side — a top-down dungeon crawler, nothing original, but a great sandbox for weird experiments. Last week I wondered: what if GPT-4o was the dungeon designer?

## The Hypothesis

LLMs are bad at spatial reasoning, or so the conventional wisdom goes. But if I give the model a constrained, token-efficient format for describing a room layout, maybe it can generate something playable.

## The Format

I defined a simple ASCII tile grammar:

```
. = floor
# = wall
D = door
C = chest
E = enemy spawn
S = player start
```

A 10×10 room looks like this in the prompt:

```
##########
#S.......#
#....E...#
#........#
###.######
#....C...#
#...E....#
#........#
#.......D#
##########
```

## Prompting Strategy

I gave GPT-4o-mini this format, a one-paragraph description of a "flooded crypt" room, and asked it to output only the grid — no explanation.

**Result:** Genuinely interesting. The model placed enemies near chokepoints, put the chest behind the secondary enemy cluster, and even added a visual indent to suggest a ruined wall. It's not always consistent, but the hit rate is high enough to be useful as a generative first pass.

## Next Steps

I want to feed multiple AI-generated rooms into a graph-based corridor connector and see if I can get a full floor that's actually navigable. The experiment continues.

This is the kind of thing that's only possible because LLMs are so cheap to call in bulk now. Generation cost per room: ~$0.0003.
